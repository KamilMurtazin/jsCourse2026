## Работа с тестами

Большинство задач курса проверяется с помощью [Vitest](https://vitest.dev/). Тесты
показывают наблюдаемое поведение решения, но не заменяют чтение условий и проверку качества
кода.

Все команды выполняются из корневого каталога курса после установки зависимостей:

```bash
yarn install --frozen-lockfile
```

### Проверить одну лекцию

Рекомендуемый режим работы — запускать только тесты текущей лекции:

```bash
yarn test "Lessons/01."
```

Vitest использует `Lessons/01.` как фильтр пути и запускает только тестовые файлы из
каталога первой лекции.

Для автоматического перезапуска после изменения файлов:

```bash
yarn test-watch "Lessons/01."
```

### Проверить одну задачу

Идентификатор задачи находится в названии её тестов. `c` означает классную работу, `h` —
домашнюю. Передайте его штатному аргументу Vitest `-t`, сохранив фильтр лекции:

```bash
yarn test "Lessons/01." -t 01.c.3
yarn test "Lessons/01." -t 01.h.2
```

Режим автоматического перезапуска:

```bash
yarn test-watch "Lessons/01." -t 01.c.3
```

### Запустить все тесты

```bash
yarn test
```

Во время работы над одной лекцией используйте её номер, чтобы результаты остальных лекций
не мешали проверке.

### Как читать результат

Vitest выводит в терминал:

- название файла и теста;
- ожидаемое и фактическое значения;
- строку, на которой проверка завершилась ошибкой;
- стек вызовов.

Сначала найдите первый упавший тест своей задачи, сопоставьте его название с требованием
из `README.md`, исправьте решение и запустите тест снова.

Если проверки запускаются в CI после отправки ветки в GitHub, полный отчёт находится в
соответствующем запуске workflow на вкладке Actions.
